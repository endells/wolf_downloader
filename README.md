# 늑대 다운로더 — wolf_downloader 0.1.4

FlaskFarm(FF)용 **독립 구현 / 실서버 검증 전 테스트 버전**입니다. 기존 `wolf_dl`의 공개 메뉴·설명을 참고해 새 Python 소스로 작성했으며, 암호화된 `.pyf` 파일은 사용하지 않습니다. 기존 플러그인과 다른 이름이므로 함께 설치할 수 있습니다.

## 현재 검증 범위

- 경로, 자동/수동 회차 선택, 임시 저장·재시도, ZIP, 작업 프로세스·잠금, 도메인 후보 처리, Flask 연동, HTML/JavaScript 렌더링: 자동 테스트 63개 통과.
- 실제 FF NAS에서의 설치·기동·CPU/메모리 사용률은 아직 측정하지 않았습니다.
- 실행 환경에서 사이트 원문이 HTTP 403 또는 `Site Unavailable`로 반환되어 **실제 작품 검색·이미지 파싱·다운로드는 검증하지 못했습니다.** 테스트용 HTML과 이미지로 기능을 검증했습니다.
- 지원하는 사이트 구조는 `/ing`, `/end`, `/list?toon=번호`, `/view?toon=번호&num=번호`입니다. 사이트 리뉴얼로 URL·HTML·JavaScript 로딩 방식이 달라지면 파서를 수정해야 합니다. 도메인 변경과 사이트 구조 변경은 서로 다른 문제입니다.
- 공개 GitHub 저장소: https://github.com/endells/wolf_downloader
- FF 플러그인 설치 화면의 Git URL 입력란에 `https://github.com/endells/wolf_downloader`를 입력해 설치하세요. 별도 GitHub 인증은 필요하지 않습니다.

## 구현 기능

| 기능 | 동작 |
|---|---|
| 다운로드 경로 | FF 폴더 선택기 사용. 지정 폴더 바로 아래 작품 폴더 생성. `manhwa` 자동 추가 없음 |
| 수동 다운로드 | URL/작품번호 분석 → 전체/미완료/반전 선택 → 선택 회차 모두 처리 |
| 완료 회차 수동 선택 | 자동 수집 상한·완료 이력과 무관하게 다시 받음 |
| 자동 수집 | 작품 목록·분 단위 예약·FF 시작 시 예약 복원·목록 지금 받기 |
| 설정 저장 | 저장만 수행. 다운로드 또는 즉시 예약 실행 없음 |
| 작품 목록/검색 | 연재·완결, 기존 필터, GET 검색 폼 자동 감지, 검색 경로 수동 지정 |
| 도메인 갱신 | 현재 주소 확인 → 공지 채널 및 이전 안내 추적 → 같은 계열 후보 검증 → 숫자 +1~+5 후보 |
| 진행 상황 | 모든 화면 상단의 작은 상태창. 회차·이미지 진행 및 중지 |
| 이력 | 별도 SQLite DB, 검색·상태 필터·페이지 구분 |
| ZIP | 완료 이미지들을 ZIP_STORED로 묶기. 이미지 재압축 없음 |
| 메타데이터 | `info.xml`과 원본 형식 표지 저장. 표지는 JPEG면 cover.jpg, PNG면 cover.png 등 |
| 기존 파일 이력 반영 | 등록 작품의 현재 경로와 기존 `manhwa/작품명` 폴더를 읽고 이미지 수 비교. 파일 이동 없음 |
| 알림 | Discord/Slack 완료 요약, 도메인 변경·전체 작업 오류 알림, 테스트 버튼 |
| 쿠키 | Cookie 헤더 입력. 저장 도메인에만 전송. 도메인 변경 시 재등록 필요 |
| 회차 번호 | 1~10자리 지정 |

원본과 차이: 기존 암호화 DB를 직접 이관하지 않고 파일을 확인해 별도 이력을 만듭니다. 기존 파일명 자동 변경·DB 전체 삭제·썸네일 프록시·Cloudflare 우회 엔진은 포함하지 않습니다. 스케줄은 이번 버전에서 분 단위만 지원합니다. 검색/필터는 사이트 구현에 따라 조정이 필요합니다.

## FF 정지 문제를 줄이는 구조

1. FF 요청 처리에서는 프로세스 시작과 짧은 상태/이력 조회만 합니다. 다운로드·HTML 파싱·압축·알림 HTTP는 새 Python 인터프리터에서 실행합니다. FF의 gevent 패치 상태를 상속하는 단순 스레드 방식과 구분됩니다.
2. 파일 잠금으로 **전체 플러그인에서 한 작업만** 실행합니다. 자동 수집 중 수동 작업, FF 재시작 후 중복 실행도 거부합니다.
3. Linux에서 가능한 경우 작업 프로세스 우선순위를 낮추고 CPU 하나에 배치합니다. 주소 공간은 512MiB 상한을 설정합니다. OS가 지원하지 않으면 해당 제한은 적용되지 않을 수 있습니다.
4. 기본 요청 간격 1.5초, 이미지 전송 상한 2MiB/s. 이미지 파일은 64KiB씩 저장하며 한 번에 전체 작품을 메모리에 올리지 않습니다.
5. 이미지 1개 32MiB, HTML 8MiB, 회차 목록 100페이지, 작품당 10,000회차, 회차당 2,000이미지 상한이 있습니다. 큰 작품/이미지는 오류를 표시하며 상한을 조정해야 할 수 있습니다.
6. 네트워크 소켓 시간 제한 15초, 이미지 요청은 최대 2회. 401/403/429 응답은 전체 작업을 멈춥니다. 인증·차단을 자동으로 우회하지 않습니다.
7. 중지는 협력 방식입니다. 네트워크 응답 중에는 다음 소켓 반환/시간 초과까지 기다릴 수 있습니다. FF와 NAS가 같은 디스크·메모리를 사용하므로 전체 NAS가 절대 멈추지 않는다는 보장은 아닙니다.

## 설치 — Portainer / 시놀로지

### 1. 기존 상태 보존

- 기존 `wolf_dl`은 삭제하지 않아도 됩니다. 동시에 다운로드하면 서로의 자원 제한을 공유하지 않으므로 기존 자동 수집은 우선 꺼 두세요.
- 새 플러그인은 `wolf_downloader`라는 별도 설정/이력 공간을 사용합니다.
- Python **3.8 이상**, Linux FF 컨테이너가 필요합니다. 런타임 추가 pip 설치는 하지 않습니다. Python 표준 라이브러리와 FF에 포함된 Flask/Jinja를 사용합니다.

### 2. FF 데이터 폴더 확인

Portainer → Containers → FF 컨테이너 → Inspect 또는 Volumes에서 FF의 데이터 폴더가 NAS 어디와 연결되는지 확인합니다.

예시 매핑(실제 설정은 사용자 환경 확인):

```yaml
volumes:
  - /volume1/docker/flaskfarm/data:/data
  - /volume2/도서:/library
```

이미 연결되어 있다면 볼륨을 추가하지 않아도 됩니다. FF의 데이터 경로가 `/data`가 아니면 아래 `/data`를 실제 경로로 바꾸세요. 컨테이너를 재생성하기 전에 기존 설정·볼륨을 그대로 보존해야 합니다.

### 3. ZIP으로 수동 설치

1. 패키지 ZIP을 PC 또는 NAS에서 풉니다.
2. 최상위 **`wolf_downloader` 폴더 전체**를 FF 데이터 폴더의 `plugins` 아래로 복사합니다.
3. 위 매핑 예시라면 NAS 경로는 `/volume1/docker/flaskfarm/data/plugins/wolf_downloader/`입니다.
4. FF 컨테이너 안에서는 다음 위치에 파일이 있어야 합니다.

```text
/data/plugins/wolf_downloader/info.yaml
/data/plugins/wolf_downloader/setup.py
/data/plugins/wolf_downloader/mod_basic.py
/data/plugins/wolf_downloader/templates/wolf_downloader_basic.html
```

`plugins/wolf_downloader/wolf_downloader/setup.py`처럼 폴더가 두 번 중첩되지 않게 합니다. FF 실행 사용자에게 읽기 권한이 있어야 하며 FF 데이터/다운로드 경로에는 쓰기 권한도 필요합니다.

5. 실행 중 다른 다운로드가 없는지 확인하고 Portainer에서 FF 컨테이너를 재시작합니다.
6. FF에서 **늑대 다운로더 → 설정**을 엽니다. 수동 폴더 설치는 FF 재시작 후 검색되는 방식입니다. 설치된 FF 버전의 플러그인 관리 화면에서 활성화가 별도로 필요할 수 있습니다.

### 4. 최초 설정

- 다운로드 경로: 예를 들어 `/library/웹툰`.
- 도메인: 브라우저에서 확인한 실제 현재 주소. 또는 비워 두고 설정 저장 후 자동 갱신.
- 도메인 계열: 기존 구조 사이트를 사용한다면 공지의 주소를 확인하여 `wftoon`을 선택할 수 있습니다. 계열이 다른 작품 ID가 같다고 가정하지 않습니다. 계열을 바꾸면 기존 자동 작품 목록도 확인하세요.
- 공지 채널: 기본 `https://t.me/s/wftoon`. 공지 채널이 다시 이전되면 직접 수정할 수 있습니다.
- 자동 수집은 일단 끄고, ZIP도 끈 상태로 첫 회차를 시험하는 것이 확인하기 쉽습니다.
- **설정 저장 → 도메인 확인** 순서로 실행합니다. 자동 갱신 성공 주소는 이후 작업에 캐시되어 사용되며 상단 상태에 표시됩니다. 설정 입력 칸을 자동 덮어쓰지는 않습니다.

### 5. 수동으로 1개 회차 확인

1. 수동 다운로드 → 작품 URL 또는 ID → 회차 분석.
2. 작품 제목과 회차가 정확한지 확인합니다.
3. 전체 선택을 해제하고 회차 하나만 선택 → 선택 회차 다운로드.
4. 지정한 폴더 바로 아래 생성된 작품 폴더와 이미지 수를 확인합니다.
5. 다운로드 중 FF의 다른 메뉴가 열리는지 확인하고 Portainer의 CPU/메모리를 비교합니다.
6. 문제가 없으면 요청 간격·전송 상한을 유지한 채 자동 목록에 추가합니다.

## 기존 작품 폴더와 작품명

- 0.1.3부터 일반 다운로드는 `작품명 [작품번호]` 폴더만 사용합니다. 번호 없는 폴더는 다른 다운로더의 폴더로 간주하여 건드리지 않습니다.
- **설정 → 기존 파일 관리 → 기존 파일 이력 반영**은 저장된 자동 수집 목록만 처리합니다. 목록에 있는 작품의 정확한 제목과 일치하는 번호 없는 폴더가 하나 있으면 `작품명 [번호]`로 이름을 바꾼 뒤 회차를 검증하여 이력에 반영합니다.
- 선택 경로와 기존 `manhwa` 바로 아래를 확인합니다. 목록 밖의 폴더는 번호 유무와 관계없이 처리하지 않습니다. 대상 폴더가 이미 있거나 후보가 여러 개이면 합치거나 덮어쓰지 않고 오류를 표시합니다.
- 이름 변경 시 해당 작품의 기존 DB 경로도 갱신합니다. 자동 수집 등록은 폴더 관리 대상을 지정하는 것이므로, 다른 다운로더와 같은 제목의 폴더를 공유하고 싶지 않다면 먼저 분리하세요.
- 사이트명으로 잘못 만들어진 폴더는 자동으로 합치거나 이동하지 않습니다. 실제 작품명을 확인하지 못하면 저장을 중지합니다.
- 기존 파일 반영은 지원하는 회차 이름과 이미지 수/ZIP 검증을 통과한 회차만 반영합니다. 수동 선택 회차는 완료 이력과 관계없이 다시 받습니다.

## 회차 파일명 정리 (0.1.4)

- 새 ZIP: `0187_화산귀환 181화 #147.zip`. `#147`은 실제 본문 이미지 147개를 의미하며 제목과 # 사이에 공백 한 칸을 둡니다.
- 사이트 회차 제목에 `187 화산귀환 181화`처럼 맨앞 목록 번호가 있으면 187을 파일 앞번호로 사용합니다. 실제 이야기 화수 181은 제목에 유지합니다. 기존 파일은 맨앞 `숫자_`로 매칭합니다.
- 기존 파일 이력 반영은 등록 작품의 ZIP을 검증하고 중복 앞번호, 날짜, 뒤의 `[회차ID]`를 제거하며 이미지 수를 추가/수정합니다.
- 앞번호가 다른 파일은 별개 회차입니다. 같은 앞번호의 ZIP은 실제 이미지 SHA-256을 비교하여 모두 같을 때만 중복으로 처리합니다. `#숫자`가 있는 정상 ZIP을 우선 유지하고, 나머지는 작품 폴더의 `.duplicates`로 옮겨 복구 가능하게 보관합니다. 내용이 다르거나 손상·파일명 충돌이 있으면 자동 삭제하지 않습니다.
- 사이트 이미지 수와 맞지 않는 기존 ZIP은 정리 대상에서 제외하고 경고합니다. 회차 폴더 안의 이미지 이름은 바꾸지 않습니다.

## 저장 구조와 재시도

```text
선택한_다운로드_폴더/
  작품명 [작품번호]/
    info.xml
    cover.jpg 또는 cover.png 등
    .wolf-work.json
    0001_회차제목/
      001.jpg
      002.jpg
      .wolf-episode.json
```

작품/회차 ID는 제목이 같은 항목의 충돌을 방지합니다. 금지 문자는 전각 문자로 바꿉니다. 이름이 지나치게 길면 UTF-8 기준 180바이트 내로 줄입니다. ZIP 사용 시 회차 폴더 대신 이름 끝에 ` #이미지수.zip`이 붙습니다.

- 완료 전 이미지는 작품 폴더의 `.download-회차ID` 아래에 있습니다. 실패·중지 시 다시 선택하면 동일 이미지 목록에 대해 정상 저장된 파일을 재사용합니다.
- 기존 완료 폴더는 새 파일이 준비된 뒤 교체합니다. 중간 종료로 `.backup-회차ID`가 남으면 자동으로 복구 가능한 경우 처리하고, 충돌 시 기존 파일을 보존하고 오류를 표시합니다.
- 본 플러그인의 소유 표식이 없는 동명 폴더/ZIP은 덮어쓰지 않습니다.
- 이력의 저장 경로가 새로 선택한 다운로드 경로 밖이면 자동 수집 시 다시 받습니다.
- 기존 파일 이력 반영은 폴더의 이미지 수를 현재 뷰어와 비교하고 ZIP은 CRC를 검사합니다. 일반 이미지 파일을 디코딩해 무결성까지 검증하지는 않으므로, 손상된 이미지가 의심되면 수동으로 다시 받으세요.
- 남은 임시 파일을 정리하려면 작업을 중지하고 프로세스 종료를 확인한 다음 필요한 `.download-*` 폴더만 직접 삭제하세요. 플러그인이 임의로 오래된 파일을 일괄 삭제하지 않습니다.

다운로드 이력의 `downloading` 행에는 현재 `.download-회차ID` 임시 경로가 표시됩니다. 진행 상황 화면에는 임시 경로와 완료 예정 경로를 구분하며, 완료 후 이력은 실제 폴더/ZIP 경로로 바뀝니다. 재다운로드 시작 시 예전 완료 경로를 진행 중 경로로 표시하지 않습니다.

## 문제 확인

| 현상 | 확인할 사항 |
|---|---|
| 도메인 자동 갱신 실패 | 계열과 공지 채널, NAS DNS·외부 접속, 사이트 차단 여부 |
| HTTP 403 / 접속 제한 | NAS에서도 브라우저로 접속 가능한지, 현재 도메인과 쿠키. 자동 우회 기능 없음 |
| 작품 분석 실패 | 현재 URL에 toon 번호가 있는지, 사이트가 기존 /list 구조인지 |
| 본문 이미지 없음 | 고급 설정 뷰어 선택자. 실제 HTML 구조에 맞춰 파서 수정이 필요할 수 있음 |
| 검색 폼 없음 | 실제 검색 결과 URL 경로에서 검색어를 `{query}`로 바꿔 검색 경로에 입력 |
| 경로가 안 보임 | Portainer의 FF 볼륨 연결. NAS의 `/volume2/...`가 컨테이너에서 같은 경로일 필요는 없음 |
| 작업 프로세스 종료됨 | Portainer 로그·메모리 제한·파일 권한. 다음 실행 시 이전 downloading 이력은 interrupted로 정리 |
| 이미 작업 중 | 상단 중지 후 종료 대기. 자동 수집과 수동/목록/압축 모두 하나의 작업 슬롯을 공유 |
| ZIP 파일이 작아지지 않음 | 이미 압축된 이미지를 무압축 ZIP으로 묶는 설계이므로 정상 |

오류 확인 시 FF 버전, Python 버전, NAS 모델, 선택 도메인 계열, 작업 상태 오류 문구를 알려주세요. 쿠키나 웹훅 주소는 공유하지 않아도 됩니다.

## 개발·검증

```bash
python -m unittest discover -s tests -v
```

표준 라이브러리 기반 핵심 테스트 54개가 실행됩니다. Flask/Jinja와 Node.js가 있는 개발 환경에서는 FF 어댑터·화면 테스트 9개도 실행됩니다. (Node.js는 플러그인 실행에 필요한 의존성이 아닙니다.)
